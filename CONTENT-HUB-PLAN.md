## 1. Buyer Persona

### Primario: Propietario de Vivienda (70% del tráfico objetivo)

| Atributo | Detalle |
|----------|---------|
| Edad | 30–55 años |
| Ubicación | Medellín — El Poblado, Laureles, Belén, Envigado, Sabaneta |
| Tipo vivienda | Casa o apartamento propio (estrato 3–6) |
| Situación gatillo | Compra vivienda nueva, renovación, vencimiento RPO, venta/arriendo |
| Necesidad principal | Seguridad + certificado legal (no negociable) |
| Miedos | Fugas, explosiones, multas EPM, que el técnico no sea certificado |
| Cómo busca | Google → "instalación gas Medellín", "técnico gas cerca de mí" |
| Canal de contacto | WhatsApp primero, llamada después |
| Objeción de compra | Precio, desconfianza del técnico, tiempos de entrega |

### Secundario: Administrador de Propiedad Horizontal / Dueño de Local Comercial (20%)

| Atributo | Detalle |
|----------|---------|
| Perfil | Administrador de conjunto, dueño de restaurante, contratista de obra |
| Lo que busca | Certificación masiva, instalación comercial NTC, proveedor confiable recurrente |
| Palabras clave | "instalación gas restaurante Medellín", "certificación conjunto residencial" |

### Terciario: Inversionista / Arrendador (10%)

| Atributo | Detalle |
|----------|---------|
| Perfil | Dueño de múltiples propiedades en arriendo |
| Lo que busca | Certificación rápida entre inquilinos, precio fijo, proveedor de confianza |
| Dolor | Que la certificación se demore y pierda el arriendo |

## 4. Taxonomía de Contenido

### Por intención de búsqueda

```
search_intent
├── informacional       → "qué es", "cómo funciona", "por qué es importante"
├── educativa           → guías, tutoriales, normativas
├── comercial           → precios, comparativas, "cuánto cuesta"
├── transaccional       → contratar, agendar, solicitar
└── emergencia          → fugas, olores, accidentes
```

### Por funnel

```
funnel_stage
├── top_of_funnel       → awareness, prevención, educación
├── middle_of_funnel    → consideración, comparación, precio
├── bottom_of_funnel    → conversión, contratación, servicio
└── retention           → post-venta, mantenimiento, cuidado
```

### Por tipo de contenido

```
content_type
├── guia_completa       → artículos exhaustivos (>1500 palabras)
├── lista               → listas, checklists, "5 señales"
├── comparativa         → vs, diferencias, cuál elegir
├── tutorial            → paso a paso, guía práctica
├── FAQ                 → preguntas frecuentes sobre un tema
└── caso_de_uso         → ejemplos reales, escenarios
```

### Por servicio relacionado

```
service_tag
├── instalacion
├── certificacion
├── mantenimiento
├── rpo
├── deteccion_fugas
├── gasodomesticos
└── calentadores
```

## 7. Optimización Técnica por Artículo

### Schema por tipo de artículo

| Tipo | Schema principal |
|------|-----------------|
| Pilar | `Article` + `BreadcrumbList` + `ItemList` (links a cluster) |
| Artículo TOFU | `Article` + `FAQPage` (si aplica) |
| Artículo MOFU | `Article` + `HowTo` (si es guía) + `Product` (si compara precios) |
| Artículo BOFU | `Article` + `FAQPage` + `Service` (call-to-action) |

### Reglas SEO por artículo

- **Title:** ≤60 chars, keyword al inicio, "Medellín" presente
- **Meta description:** 140–160 chars, keyword + CTA + " — LujoGas"
- **H1:** único, keyword principal + "en Medellín"
- **H2/H3:** variaciones de keywords + preguntas naturales
- **Internal linking:** ≥3 links a páginas de servicio + ≥2 links a otros artículos del cluster
- **CTA:** botón WhatsApp contextual (no genérico) al final + inline cada ~400 palabras
- **Imágenes:** alt text descriptivo con keyword. WebP/AVIF.
- **Extensión:** TOFU 1200–1800 palabras, MOFU 1500–2500, BOFU 1000–1500

## 12. Implementación Técnica Recomendada

### Prioridades para el código

1. **Content Collections** en Astro (`src/content/blog/`) — schema frontmatter con slug, title, description, category, tags, intent, funnel
2. **Páginas pilar** — Astro pages con lista de artículos del cluster
3. **Artículos individuales** — `[slug].astro` con renderizado de MD/MDX
4. **Dynamic sitemap** — actualizar `astro.config.mjs` para incluir blog posts
5. **Schema dinámico** — componente `<BlogSchema />` que genere Article + FAQ + Breadcrumb según frontmatter
6. **llms.txt** — agregar automáticamente los nuevos artículos
7. **Pagination** en `/blog/` si se superan 10 artículos
8. **RSS feed** — para syndication y actualizaciones

### Prioridad de implementación

```
Fase 0 (pre-contenido):
  └── src/content/ + esquema frontmatter + [slug].astro

Fase 1 (semana 1):
  └── 4 páginas pilar + /blog/index.astro + schema blog

  └── 24 artículos del cluster (8 por semana)

  └── internal linking automático + sitemap dinámico + llms.txt update
```

#### Fortalezas de Accegas

| Factor | Detalle |
|--------|---------|
| **Cobertura de keywords** | Cada combinación servicio×ubicación es una URL única. Capturan cola larga geolocalizada. |
| **Breadcrumbs profundos** | 3-4 niveles en todas las páginas. Señal de relevancia para Google. |
| **Consistencia estructural** | Todas las páginas siguen la misma plantilla. Escalable. |
| **Tiempos de respuesta** | Promedio 30 min para emergencia, 24-48h programado. Expectativa clara. |
| **Garantía** | 3 meses en todos los servicios. Diferenciador. |
| **Stack técnico** | Next.js con imágenes optimizadas (next/image, WebP). Buen performance. |
| **Marcas aliadas** | Logos de Bosch, Challenger, Haceb, Mabe, Rheem, Rinnai. Autoridad por asociación. |

#### Debilidades de Accegas

| Factor | Detalle | Cómo explotarlo |
|--------|---------|-----------------|
| **Contenido thin** | Las páginas servicio×ubicación cambian solo el nombre de la zona. Mismo texto de relleno. | LujoGas puede crear contenido ÚNICO por zona: datos locales, barrios específicos, tiempos reales, casos. |
